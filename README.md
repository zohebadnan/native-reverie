## 🏛️ What Is native-legacy?

**native-legacy** is an ambitious, community-driven restoration framework dedicated to reviving and preserving the look, feel, and soul of early online sandbox worlds — specifically those that thrived between **2006 and 2014**. Think of it as a time capsule, but one you can actually open, walk through, and rebuild brick by brick alongside other enthusiasts.

This project is not merely an archive. It is a *living workshop*. While traditional preservation efforts freeze history behind glass, native-legacy hands you the tools to breathe motion back into it — restoring classic physics behavior, legacy UI paradigms, vintage asset pipelines, and the nostalgic networking quirks that defined an entire generation of player-built universes.

Whether you're a hobbyist historian, a retro-software researcher, a modder, or simply someone who misses the simplicity of older client-server architecture, native-legacy offers a structured, respectful, and technically rigorous path into that world.

## 🎯 Project Vision

The digital landscapes we grew up in are vanishing. Servers shut down. Assets go dark. Entire communities scatter to the wind. native-legacy exists to counter that entropy.

Our vision is a **perpetually maintained, fully documented restoration environment** where:

- Legacy behavior is reproduced faithfully, not approximated.
- Modern hardware can run decade-old software smoothly and securely.
- Contributors of all skill levels can participate meaningfully.
- The knowledge embedded in these old systems is not lost to time.

We treat this work like archaeology with a compiler. Every recovered function, every reconstructed interface, every reimplemented protocol is a fragment of a larger story worth telling.

## ✨ Core Features

### 🧩 Faithful Restoration Layer
native-legacy reproduces early-era runtime behavior with painstaking attention to detail. Physics tick rates, rendering fallbacks, input latency profiles, and legacy scripting semantics are all modeled so that restored projects feel authentic rather than merely similar.

### 🖥️ Responsive Interface Framework
The restored tooling adapts to monitors of every shape and size. Legacy window chrome meets contemporary layout principles, giving you a workspace that honors the past while remaining pleasant on modern displays.

### 🌍 Multilingual Support
Restoration should not be gated behind a single language. native-legacy ships with internationalization baked in, supporting contributors and players across many regions. Community translation packs are welcomed and continuously integrated.

### 🕰️ Era-Accurate Versioning
Projects can be pinned to specific historical snapshots. Want the 2008 feel? The 2011 networking model? The system maintains parallel compatibility profiles so each restoration remains true to its chosen moment in time.

### 🛎️ Round-the-Clock Community Assistance
Questions do not keep business hours, and neither does our support philosophy. Maintainers and veteran contributors coordinate across time zones so that guidance is available whenever inspiration strikes.

### 🧪 Sandboxed Experimentation
Test reconstructed systems in isolated environments before committing them to your main workspace. Roll back, branch out, and compare versions without fear of breaking your primary restoration.

### 📚 Extensive Documentation Vault
Every subsystem is documented with historical context, technical notes, and practical examples. The goal is comprehension, not just configuration.

### 🤝 Contributor-Friendly Architecture
Modular components, clear interfaces, and generous inline guidance make it easy for newcomers to submit their first improvement within an afternoon.

### 🔐 Privacy-Respecting Design
No telemetry, no tracking, no hidden data collection. Your restoration work stays yours.

## 🚀 Getting Started

Getting native-legacy running is designed to be approachable regardless of your background. The environment is self-contained and includes everything needed to begin exploring.

1. **Acquire the release package** using the distribution marker shown near the top of this document.
2. **Unpack the archive** into a directory of your choosing. Avoid paths containing unusual characters, as some legacy modules are sensitive to encoding.
3. **Launch the bootstrap utility** included in the root of the package. It will detect your platform and prepare the appropriate runtime components.
4. **Select a restoration profile** from the built-in catalog — choose an era, a target feature set, and an optional asset bundle.
5. **Begin exploring.** The workspace opens with sample projects already staged so you can see the system in action immediately.

No prior experience with legacy systems is required. The onboarding flow walks you through each step with contextual explanations.

## 🧭 Repository Structure

A high-level tour of the major directories:

- **/core** — The heart of the restoration engine. Contains runtime abstractions, compatibility shims, and era-profile definitions.
- **/interface** — All UI-related modules, including the responsive layout system and theming engine.
- **/assets** — Sample asset bundles and restoration templates for demonstration purposes.
- **/docs** — The full documentation vault, organized by subsystem and era.
- **/locales** — Translation resources and language packs.
- **/tools** — Utility scripts for packaging, validation, and environment diagnostics.
- **/tests** — Automated verification suites ensuring restoration fidelity across profiles.

Each directory contains its own focused documentation to guide contributors toward the right layer.
